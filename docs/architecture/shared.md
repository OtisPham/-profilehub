# Shared Architecture Specification (TypeScript Contracts)

## 1. Purpose & Scope

The `shared/` directory contains cross-tier code shared strictly between the React Frontend (`frontend/`) and Node.js/Supabase Backend (`backend/`).

---

## 2. Directory Structure (`shared/`)

```text
shared/
├── dto/                          # Data Transfer Objects for API requests/responses
│   ├── aiCvDto.ts
│   ├── aiInterviewDto.ts
│   └── pipelineDto.ts
├── types/                        # Core Domain & Database entity interfaces
│   ├── database.ts               # Autogenerated Supabase DB Type definitions
│   └── portfolioMatch.ts         # Portfolio match scoring models
├── validations/                  # Input validation schemas (Zod/Joi)
│   ├── jobSchema.ts
│   └── profileSchema.ts
├── constants/                    # System-wide constants & enums
│   ├── roles.ts                  # 'student' | 'teacher' | 'recruiter'
│   └── pipelineStages.ts         # 'discovered' | 'contacted' | 'interviewing' | 'hired'
└── utilities/                    # Pure, side-effect-free helper functions
    ├── jobSync.ts                # Job state synchronization helper
    └── pipelineSync.ts           # Kanban stage transition helper
```

---

## 3. Boundary Rules

1. **Zero External UI Dependencies**: `shared/` MUST NOT depend on React, Vite, Tailwind, HTML DOM, or UI libraries.
2. **Pure TypeScript**: Code in `shared/` must be pure TypeScript runnable in both Node.js and browser environments.
3. **Single Direction**: Both `frontend/` and `backend/` may import from `shared/`, but `shared/` CANNOT import from `frontend/` or `backend/`.
